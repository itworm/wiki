# Skill 工程方法论

AI Skill 从"自己能用的"到"别人敢用的"所需的验证、版本与交接体系。

## 四层诊断框架

| 层 | 核心问题 | 解决手段 |
|----|---------|---------|
| 输入层 | 信息不足时继续装懂 | 开工闸门，暴露已知/未知 |
| 过程层 | 一步到位无确认节点 | 拆解步骤，错误回退 |
| 输出层 | 结构与标准模糊 | 明确格式+自查清单 |
| 验证层 | 改完凭感觉 | 版本记录+复测+失败记录 |

## 关键实践

- **事实标签**：输出区分已确认 vs 推断
- **单条修改**：每次只改一条规则，记录修改原因和验证结果
- **30分钟极速迭代**：选小任务→跑V1→找一个问题→判断层级→改一条

## 真正的提效：不是写更多 Prompt，而是把经验沉淀为 Skill ⭐⭐

> ⭐ **"真正的提效，不是写更多 Prompt，而是把经验沉淀为 Skill。"**
> ⭐ **"AI 时代的核心竞争力，是把重复劳动变成数字资产的能力。"**

**两种"提效"的区别：**

| | **写 Prompt** | **沉淀 Skill** |
|---|---|---|
| 产物 | 一段对话里的指令 | **可复用的过程资产** |
| 复用性 | 下次要重写 / 找不到 | **一次写好，永久调用** |
| 归属 | 散落在聊天记录里 | **在版本库里** |
| 是否会积累 | ❌ 每次从零开始 | ✅ **越用越准（可迭代）** |
| 人的成长 | 熟练度 | **方法论显性化** |

> ⭐ **关键差别在"是否可积累"** —— Prompt 用完即散，Skill 用完还在，而且能改。
> 这就是为什么"把重复劳动变成**数字资产**"比"提高效率"更值钱——**效率提升是一次性的，资产是可以反复生息的**。

**判断标准（自问）**：这件事我是不是第二次做了？如果是，它就该变成 Skill，而不是再写一遍 Prompt。
